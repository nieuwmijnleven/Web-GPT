# 네트워크 시퀀스 분석

## 개요

ShortsMonitor는 YouTube Shorts 화면의 **DOM 목록**과 **서버가 전달한 추천 시퀀스**를 별개의 데이터로 수집한다.
중간 삽입 판정은 네트워크 시퀀스 비교를 기준으로 수행하며, DOM 정보는 실제 노출 여부와 메타데이터 보완에만 사용한다.

## DOM 목록과 서버 시퀀스의 차이

| 항목 | DOM 목록 | 서버 시퀀스 |
| --- | --- | --- |
| 출처 | 페이지 DOM 관찰 | `reel_watch_sequence` 네트워크 응답 |
| 의미 | 실제 렌더링된 항목 | 서버가 전달한 추천 순서 |
| 지연 | 렌더링/가상 스크롤에 따라 늦게 나타남 | 요청 시점 기준 즉시 |
| 활용 | 노출 순서, 제목·채널 등 메타데이터 보완 | 중간 삽입 판정 기준 |

DOM 지연 렌더링은 확정 삽입으로 기록되지 않는다. DOM 스냅샷만으로 삽입 이벤트를 생성하지 않는다.

## 네트워크 시퀀스 분석 방식

1. 문서 시작 시점에 `fetch`와 `XMLHttpRequest`를 관찰한다 (문서 시작 주입 미지원 환경은 제한 상태로 표시).
2. 관찰 대상: `reel_watch_sequence`, `reel_item_watch`, `player`.
3. `fetch`는 반드시 `clone()`을 읽고, `XMLHttpRequest`는 `addEventListener`로만 추가 관찰한다. 원본 요청/응답 동작은 변경하지 않는다.
4. 요청 본문에서 `sequenceParams`, continuation 계열 값을 안전한 형태(디코딩된 영상 순서, 해시, 길이, 오류 코드)로만 저장한다.
5. 응답에서 영상 식별값, 위치, 엔트리 종류, 현재 영상 여부, continuation 존재 여부 등을 여러 후보 경로로 방어적으로 추출한다.
6. 각 시퀀스의 계보를 판정해 같은 추천 흐름의 갱신인지 새 탐색인지 구분한다.

## 삽입 후보와 확정의 차이

- **후보(CANDIDATE)**: 네트워크 시퀀스 비교로 중간 삽입이 의심되는 상태.
- **확정(CONFIRMED)**: 같은 계보의 후속 시퀀스, 해당 영상의 `player`/`reel_item_watch` 요청, DOM 활성 노출 등 충분한 증거 조합이 있을 때만 부여.
- **보류/미상(UNKNOWN)**: 네트워크 데이터가 없거나 계보가 불명확하면 자동 확정하지 않는다.

## 초기 시퀀스 누락 시 제한

문서 시작 주입을 지원하지 않는 환경에서는 초기 `reel_watch_sequence` 요청을 놓칠 수 있다.
이 경우 세션을 제한 상태로 표시하고 삽입 분석 신뢰도를 낮춘다. 초기 요청을 놓친 세션에서 중간 삽입을 확정하지 않는다.

## WebView 환경별 관찰 한계

- 문서 시작 스크립트 지원 여부는 환경(Android System WebView 버전)에 따라 다르다.
- 지원 여부와 관찰기 설치 시각, 첫 Shorts 요청 시각을 기록하고 진단 화면에 표시한다.
- 고정 HTML 테스트만으로 실제 YouTube 호환성을 증명했다고 단정하지 않는다. 실기기 확인이 필요하다.

## HAR 분석 범위

첨부 `m.youtube.com.har` 분석은 특정 검색 진입 세션에 한정된다. 해당 범위에서는 중간 삽입, 재배치, 교체, 추가 피드 배치 요청, `softRefreshContinuation` 갱신이 확인되지 않았다.
이를 YouTube 전체 동작으로 단정하지 않으며, 여러 응답 형태를 수용하는 방어적 파서를 유지한다.

## 한계 고지

현재 구현은 YouTube 내부 알고리즘을 완전히 재현하거나 증명하지 않는다. 서버 응답 구조 변경 시 파싱이 제한될 수 있으며, 관찰 가능한 신호의 조합으로만 판정한다.

## 보안 지침

- HAR에 포함된 쿠키, 토큰, 방문자 식별값, 세션 값, 네트워크 주소를 코드·문서·테스트 데이터·로그·커밋에 복사하지 않는다.
- `sequenceParams`, continuation, 추적 파라미터 원문은 저장하지 않는다. 해시/존재 여부/길이만 저장한다.
- 브리지 메시지는 데이터로만 파싱하며, 메시지 크기·시퀀스 항목 수·문자열 길이·깊이 제한을 적용한다.
- 로그에는 민감정보를 남기지 않는다. 진단 화면과 내보내기 데이터에도 민감 원문을 포함하지 않는다.
