# Threat model

Residual risk is material because the requested design preserves arbitrary DevSpace tools. The table records the boundary, scenario, impact, mitigation, detection, and recovery for each required threat class.

| Threat / boundary | Scenario and impact | Mitigation | Detection | Recovery / residual risk |
|---|---|---|---|---|
| Prompt injection / repository content → model | A README, issue, or source file tells ChatGPT to exfiltrate a secret or run a destructive command. | Treat all tool output as untrusted; follow only the user request; require confirmation for writes. | Review conversation/tool audit and DevSpace tool logs. | Stop services, rotate secrets, restore Git/files; a trusted app can still be persuaded. |
| Malicious source file → build/runtime | A project hook or script executes during a build. | Disposable workspace validation; dedicated account; explicit human review of commands. | Process/service logs and file diffs. | Revoke app/tunnel, isolate workspace, remove dependency/hook; arbitrary shell remains enabled. |
| Malicious command output → model | Output contains instruction-like text or a secret. | No automatic follow-up invocation; logs bound previews and redact transport secrets. | Inspect tool result and logs. | End session and rotate exposed credentials; output can still influence a model. |
| Arbitrary command execution / filesystem destruction | `bash` deletes or overwrites project data. | Allowed-root containment, account ACL, ChatGPT confirmation, backups/version control. | Tool-call logs, Git status, filesystem monitoring. | Stop DevSpace, restore from Git/backup; root-contained destruction is still possible. |
| Credential exposure | A command reads env files or process state. | Secrets outside workspace, restrictive modes, no secret args, separate runtime key, no raw HTTP logs. | Secret scanning and audit logs. | Revoke/rotate immediately; assume any readable workspace secret is compromised. |
| Dependency supply chain | Package install/build fetches malicious code. | Verify official DevSpace package/source and tunnel checksum; do not auto-install from tool output. | Package lock review, checksum records, host monitoring. | Rebuild from trusted artifacts and rotate credentials; service account limits blast radius. |
| Malicious package installation | ChatGPT installs a package with install hooks. | Native confirmation and disposable tests; no package allowlist is claimed. | npm/apt logs and changed files. | Remove package, restore lockfiles, rotate secrets; arbitrary package operations remain possible. |
| Git remote manipulation | Tool changes remotes or pushes sensitive/destructive history. | Dedicated account, review Git commands, no automatic retry. | Git config/diff/audit logs. | Disable app credentials, reset remote configuration, recover refs; pushes are not prevented. |
| Destructive Git operations | Force reset or branch deletion loses work. | Confirmation and worktree option; backups before migration. | Git reflog/status and tool logs. | Recover reflog/remote backup; uncertain execution may leave partial state. |
| Database destruction | Shell drops or mutates a database reachable from the workspace. | No production destructive tests; least-privilege service account and separate database credentials. | Database audit logs and service logs. | Stop app, restore database backup, rotate credentials; network-reachable databases are residual risk. |
| Container escape | Bash reaches Docker/LXD and obtains host-level control. | Do not add container groups to `devspace`; dedicated account has no sudo. | Docker/LXD audit and host monitoring. | Revoke/stop service and investigate host; existing group/device policy must be reviewed separately. |
| Network pivoting | Bash scans or calls internal services. | Tunnel has outbound-only control path; no public DevSpace port; service account network access is not otherwise filtered. | Egress/firewall and process telemetry. | Isolate VPS and rotate credentials; shell network capability remains. |
| Privilege escalation | A command abuses a local binary or writable path. | `NoNewPrivileges`, no sudo, package path read-only, dedicated account. | OS audit and journal. | Disable units, patch host, rotate secrets; kernel/host vulnerabilities are outside this setup. |
| Confused deputy | ChatGPT uses DevSpace credentials or allowed root for a different user’s request. | User-scoped OAuth, workspace app review, explicit roots, no public URL. | OAuth/app audit and DevSpace request logs. | Revoke tokens and unpublish app; authorized users still share the account’s workspace scope. |
| Cross-session data exposure | A stale workspace/session ID is reused by another conversation. | Session registry, OAuth bearer checks, idle cleanup, workspace IDs scoped by server state. | Session logs and unexpected workspace IDs. | Restart DevSpace and revoke OAuth tokens; inspect state DB. |
| Replay / duplicate execution | A timeout causes a non-idempotent call to be repeated. | No automatic retry in a gateway; confirmation for writes; inspect result before retrying. | Tool duration/error logs and application audit. | Reconcile Git/files/database state; uncertain non-idempotent results remain possible. |
| Tunnel credential compromise | Runtime key is copied from the VPS or logs. | Separate restricted key, file/env reference, mode 0640, no admin key in service. | Platform key audit and file access logs. | Revoke key, issue a new runtime key, restart tunnel; tunnel ID itself is not a secret. |
| DevSpace compromise | Local MCP server or npm dependency is tampered with. | Official package/source verification, loopback binding, service account, checksum records. | File/package integrity and journal. | Stop service, reinstall trusted version, restore config; local user/root compromise defeats controls. |
| ChatGPT account compromise | An attacker invokes the published app. | Business admin-only developer mode, app permissions, confirmation, workspace publishing review. | Workspace app/compliance logs. | Unpublish/disable app, revoke OAuth, rotate secrets; ChatGPT policy can block or allow actions by context. |
| Administrator misuse / publishing mistake | An admin publishes all eight powerful actions to a broad workspace. | Draft testing, action review, narrow workspace association, explicit publish handoff. | Workspace settings and audit events. | Unpublish/restrict app and rotate credentials; full DevSpace access is intentionally powerful. |
